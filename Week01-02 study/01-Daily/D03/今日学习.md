## 📝 GitHub 四大类比

| 概念 | 类比 | 我的理解 |
|------|------|----------|
| Repository | 实验室笔记本 | 一个项目所有文件 + 历史的容器 |
| Commit | 带日期的一页 | 一次有意义的改动 + 说明信息 |
| Branch | "如果……"草稿纸 | 独立于主线的实验，不怕改坏 |
| Pull Request | 同伴互评 | 请求别人审查你的改动再合并 |

## 💭 三行反思

**第一行 — 今天学到了什么？**
GitHub 不只是"存代码的地方"，它是你的实验记录本。每次 commit 是一页，commit message 就是那页的标题。好的 commit message 描述"做了什么"而非"改了哪个文件"。

**第二行 — 今天遇到的困难？**
commit message 的粒度控制——什么时候该拆成两次 commit，什么时候合并为一次？原则：一次 commit = 一次有意义的改动。

**第三行 — 明天要做什么？**
