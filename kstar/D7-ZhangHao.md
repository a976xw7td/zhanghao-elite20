## T — Task（任务）

**具体任务：** 用 AI 生成一段 100 字以内的学习摘要，覆盖三个核心概念，面向非技术背景大学生。

**验收标准（Done means...）：**
1. ✅ 三个核心概念（3D框架、KSTAR、GitHub）全部被提及
2. ✅ 总字数 ≤ 100 字
3. ✅ 用自然段落形式（非列表）
4. ✅ 没有任何未解释的英文缩写（如 MCP、API 等）
5. ✅ 一个完全不懂 AI 的大学生读完后能说出这三个概念分别是什么
6. ✅ 文件提交到 `prompts/D4-P2.md`

## A — Action（行动）

**执行步骤：**
1. 草拟提示词 v1（包含三个要点 + 字数限制 + 受众说明）
2. 发送提示词给 AI
3. 逐条对照验收标准检查输出 → 发现字数超了（约150字）
4. 追加迭代提示："压缩到100字以内，删掉过渡词"
5. 再次检查 → 字数合格，但"GitHub"对非技术读者不够清晰
6. 追加第三次提示："给 GitHub 加一句话解释"
7. 最终输出符合全部 6 项验收标准
8. 保存提示词 + 输出 + 反思到 `prompts/D4-P2.md`

**迭代次数：** 3 轮（初版 + 压缩字数 + 补充解释）

**学到了什么：**
1. 第一次提示词几乎不可能完美——好输出是迭代出来的，不是一次性写出来的
2. 验收标准在检查阶段才真正发挥作用——没有它，我会在"感觉还行"时就停下来
3. "面向非技术读者"这条约束比我想的更难执行——需要刻意删掉所有不自觉冒出来的术语
4. R 会反哺 K：现在我知道了，写摘要提示词时，在 K 阶段先列出"要避免的术语清单"会省很多迭代
